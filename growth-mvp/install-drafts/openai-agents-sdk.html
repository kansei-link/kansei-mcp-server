OpenAI Agents SDK（Python）に KanseiLink を接続する

MCPServerStdio でKanseiLinkをエージェントのツールとして渡します。前提: Python 3.9以上・pip install openai-agents 済み・Node.js 18以上（npx実行用）。

1. 接続コード（コピーして貼り付け）

import asyncio
from agents import Agent, Runner
from agents.mcp import MCPServerStdio

async def main():
    async with MCPServerStdio(
        params={"command": "npx", "args": ["-y", "@kansei-link/mcp-server"]},
        cache_tools_list=True,
    ) as kansei_link:
        agent = Agent(
            name="Assistant",
            instructions="SaaS連携の前にKanseiLinkでサービス情報を確認してください。",
            mcp_servers=[kansei_link],
        )
        result = await Runner.run(agent, "freee会計と連携する準備をして")
        print(result.final_output)

asyncio.run(main())

TypeScript版SDK（@openai/agents）での設定形式は公式ドキュメント確認中のため、本ページではPython版のみ記載しています。

2. 接続確認（1コマンド）

パッケージ本体がローカルで起動できるかは、次の1コマンドで確認できます（transmission: OFF (Local Mode) と表示されれば正常）。

npx -y -p @kansei-link/mcp-server kansei-link-privacy --status

SDKからツール一覧が取得できるかは、次の短いスクリプトで確認します。search_services / lookup / report が表示されれば接続できています。

import asyncio
from agents.mcp import MCPServerStdio

async def check():
    async with MCPServerStdio(params={"command": "npx", "args": ["-y", "@kansei-link/mcp-server"]}) as s:
        print([t.name for t in await s.list_tools()])

asyncio.run(check())

3. うまくいかないときの自己診断（代表的な設定ミス3種）

  1. async with を使っていない MCPServerStdio は接続の確立が必要です。async with（または明示的な connect()）なしでAgentに渡すとツールが見えません。
  2. mcp_servers への渡し忘れ Agent(...) の引数 mcp_servers=[kansei_link] を忘れると、サーバーは起動してもエージェントからツールが呼べません（tools とは別の引数です）。
  3. npx がPATHにない Pythonの実行環境（仮想環境・コンテナ・CI）にNode.jsが入っていないと起動に失敗します。node -v（v18以上）と npx --version を確認してください。

4. 削除手順

コードから MCPServerStdio ブロックと mcp_servers 引数を削除するだけです。常駐設定はありません。ローカルに残るnpxキャッシュは npx clear-npx-cache で削除できます。

Live Updates（利用データの送信を伴う更新通知）は任意・デフォルトOFFです。有効化する場合のみ、同意文（README「Live Updates」節）をご確認ください。
