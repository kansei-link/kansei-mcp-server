KanseiLink — MCP Install Guide
所要時間: 約1分

Gemini CLI に KanseiLink を追加する

settings.json に1ブロック追記するだけです。前提: Node.js 18以上。

1. settings.json に追記（コピーして貼り付け）

ユーザー単位~/.gemini/settings.json
プロジェクト単位リポジトリ直下の .gemini/settings.json
{
  "mcpServers": {
    "kansei-link": {
      "command": "npx",
      "args": ["-y", "@kansei-link/mcp-server"]
    }
  }
}

既存の設定がある場合は mcpServers の中にエントリだけを追加してください。

ファイルを直接編集する代わりに、コマンド1行で追加することもできます（既定はプロジェクト単位。ユーザー単位にする場合は -s user を付加）。

gemini mcp add kansei-link npx -y @kansei-link/mcp-server

構文は gemini mcp add [options] <name> <command> [args...] です。npx 以降の引数の前に -- 区切りは不要です（付けると引数不足エラーになります）。参考: Gemini CLI公式ドキュメント「MCP servers」（gemini-cli v0.55.1にて上記コマンドで正しい設定が書き込まれることを実機確認済み）。

2. 接続確認（1コマンド）

Gemini CLIを起動し、次を入力します。

/mcp

一覧に kansei-link と、ツール search_services / lookup / report が表示されれば完了です。

3. うまくいかないときの自己診断（代表的な設定ミス3種）

  1. ファイルの場所違い ユーザー設定はホームディレクトリの ~/.gemini/settings.json です。作業ディレクトリに新規作成した場合はプロジェクト設定（.gemini/settings.json）として扱われ、他のディレクトリでは読み込まれません。
  2. JSONの構文エラー カンマの過不足・引用符の欠落があると設定全体が読み込まれず、/mcp に何も表示されません。
  3. Node.js/npxの未導入 node -v で v18 以上を確認してください。npxが見つからない環境ではサーバーの起動に失敗します。

4. 削除手順

settings.json から "kansei-link" のエントリを削除し、Gemini CLIを再起動してください。
