KanseiLink — MCP Install Guide
所要時間: 約1分

VS Code に KanseiLink を追加する

VS CodeのMCP対応（GitHub Copilot agent mode・VS Code 1.102以降でMCP正式対応）向けの手順です。前提: Node.js 18以上。

1. .vscode/mcp.json を作成（コピーして貼り付け）

VS Codeは mcpServers ではなく servers キーを使います（Cursor形式と異なる点に注意）。

{
  "servers": {
    "kansei-link": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@kansei-link/mcp-server"]
    }
  }
}

ワークスペース単位なら上記をリポジトリ直下の .vscode/mcp.json に。ユーザー単位で使う場合はコマンドパレットの「MCP: Open User Configuration」から同じ内容を追記します。

2. 接続確認（1コマンド）

コマンドパレット（Ctrl/Cmd+Shift+P）で次を実行します。

MCP: List Servers

一覧に kansei-link が「Running」で表示され、Copilot Chat（agent mode）のツール一覧に search_services / lookup / report が出ていれば完了です。

3. うまくいかないときの自己診断（代表的な設定ミス3種）

  1. キー名の混同（mcpServers と servers） Cursor/Claude Desktop形式の mcpServers をそのまま貼ると読み込まれません。VS Codeの mcp.json は servers キーです。
  2. 置き場所違い・旧形式の残留 ワークスペース設定は .vscode/mcp.json です。過去に settings.json 内へ書いた旧形式（"mcp" セクション）が残っている場合の移行手順は公式ドキュメント確認中です——両方に定義がある場合はまず片方に統一してください。
  3. MCP/agent modeが無効 組織ポリシーや設定（chat.mcp.enabled）でMCPが無効化されているとサーバーは起動しません。設定を確認してください。

4. 削除手順

.vscode/mcp.json（またはユーザー設定）から "kansei-link" のエントリを削除してください。「MCP: List Servers」から個別に停止することもできます。
