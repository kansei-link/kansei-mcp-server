Chatwork MCP｜公式サーバーの有無とつなぎ方（2026年10月時点）

Chatwork（株式会社kubell）の公式 MCP サーバーについて、2026-10-22 に一次資料で確かめた範囲を書いています。

公式 MCP あり
Chatworkには、提供元の株式会社kubellが公開する公式の MCP サーバーがあります（2026-10-22 確認）。 GitHub の chatwork 組織と npm（作者 kubell Co., LTD）で配布されていますが、会社のニュースでの告知は見つかっていません。

公式 MCP サーバーの所在とつなぎ方

提供元株式会社kubell
所在リポジトリ: https://github.com/chatwork/chatwork-mcp-server
npm @chatwork/mcp-server（1.0.0・2026-09-25）
提供の形自分の環境で動かす（ローカル）／自分で HTTP サーバーとして立てる
既定は stdio のローカル実行。--transport http で自分で HTTP サーバーとして立てることもできる（提供元が運用するリモート版はない）。
認証方式Chatwork API トークン。stdio では環境変数 CHATWORK_API_TOKEN、HTTP モードではリクエストヘッダ Authorization: Bearer で渡す（ヘッダが無いと 401）。README に「このサーバは OAuth に対応していない」と明記。
開発者向けサイトの API は API トークンと OAuth 2.0 の両方を文書化していますが、MCP サーバーが使うのは API トークンだけです。API の利用には組織管理者への申請が必要（パーソナルプランを除く）。
公式の手順chatwork-mcp-server README（Claude Desktop／Claude Code の設定例）
但し書きREADME に「公式」の語はないが、提供元の組織と会社名義で配布。ベータ等の但し書きなし。不具合・要望は GitHub Issues へ。

手順そのものは提供元の文書に従ってください。ここには写しません。認証方式は README だけでなく、提供元の文書全体から読み取った範囲で書いています。

詰まりどころ

このサービスについての現場メモは、まだありません。

Chatwork のエラーで止まったら: GET https://kansei-link-mcp-production.up.railway.app/api/v1/ask?service=chatwork&error=<短いエラー文> で、確認済みの解決策（あれば）と公式ドキュメントが返ります。読み取りだけで、何も公開されません。エラー文に鍵やトークンを入れないでください。長い文は同じ欄を JSON で POST。
