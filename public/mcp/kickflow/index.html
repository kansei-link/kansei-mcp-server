公式 MCP サーバーの所在とつなぎ方

提供元株式会社kickflow
所在リポジトリ: https://github.com/kickflow/kickflow-mcp-server
npm @kickflow/mcp-server（2026-10-21 時点 1.5.5）
提供の形自分の環境で動かす（ローカル）
npx で動かすローカルサーバー（stdio）。提供元が運用するリモート版は公式の情報にはありません。
認証方式kickflow のアクセストークンを環境変数 KICKFLOW_ACCESS_TOKEN で渡す。トークンは kickflow のアクセストークン設定画面で発行する Personal Access Token（REST API の文書では Service Account Token も定義され、漏洩時の影響が大きいので必要でない限り Personal Access Token を勧めている）。
開発者向けサイトの MCP ページは認証に触れず README を案内しています。OAuth の記載はありません。
公式の手順kickflow-mcp-server README（developer.kickflow.com/mcp/ からも案内）
但し書きNode.js v22.18.0 以上が必要。ツールは discover_apis・get_api_info・call_api の 3 つで、REST API 全体（参照・更新）を扱う。ベータ等の但し書きなし。

手順そのものは提供元の文書に従ってください。ここには写しません。認証方式は README だけでなく、提供元の文書全体から読み取った範囲で書いています。

kickflow のエラーで止まったら: GET https://kansei-link-mcp-production.up.railway.app/api/v1/ask?service=kickflow&error=<短いエラー文> で、確認済みの解決策（あれば）と公式ドキュメントが返ります。読み取りだけで、何も公開されません。エラー文に鍵やトークンを入れないでください。長い文は同じ欄を JSON で POST。
