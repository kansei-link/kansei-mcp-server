日本の SaaS の公式 MCP — ARD の一覧

AI エージェントが「どこに公式の MCP があるか」を機械で見つけられるように、私たちの記録を ARD（Agentic Resource Discovery）の形で公開しています。人が読むための一覧がこのページです。

これは何か

機械向けの本体は /.well-known/ard.json（28 エントリ）です。日本の SaaS 26 社の公式 MCP、KanseiLINK 自身の MCP サーバー、この一覧を取得する API の定義（OpenAPI）が入っています。順位でも評価でもなく、一次資料で確かめた所在の記録です。

記録の段階 — 存在確認だけの記録を「検証済み」とは書きません
・L0 存在確認: 提供者自身の発表・文書・リポジトリで、公式の MCP があることを確かめた。つながるかどうかは確かめていません。
・L1 到達確認: 封印した問いで、AI が公式の所在に辿り着けるかを毎日測った。
・L2 接続確認: 実際に起動・接続して、操作の定義を取得した。
・L3 業務完了確認: 業務を最後まで終えた。今は該当なし。
今の内訳: L0 が 26 件、L1 以上が 1 件（KanseiLink MCP Server（Synapse Arrows PTE. LTD.））。

1 件は観測期間中のため 2026-10-28 以降に追加します。

「問いの例」（representativeQueries）は KanseiLINK が書いた物で、提供者の言葉ではありません。提供形態と認証は一次資料に書かれていた範囲で、書かれていなければ「一次資料に記載なし」としています。作成主体は kansei-link.com、L1 以上の検証主体は human:synapse-arrows です。

機械で読む人へ

・manifest: https://kansei-link.com/.well-known/ard.json（仕様: ards-project/ard-spec spec/ard.md v0.91 (b76f235, 2026-09-12)）
・kansei: の語の定義: /ns/ard/v1.jsonld（説明は /ns/ard/v1）
・各エントリの url は、取得を数えるために私たちのサーバーのカードを指します。公式の所在はカードの official.location です。取得の数は /ard/stats.json に出しています（記録するのは時刻・経路・User-Agent・Referer・Accept だけで、IP は記録しません）。
・エラーは RFC 9457 の形で返します: ard-entry-not-found・bad-request

記録の誤りの指摘・訂正は 独立性のポリシー の窓口へ。提供者からの訂正は一次資料に合わせて直します。
