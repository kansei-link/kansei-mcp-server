KanseiLinkAgent Field Notes
PROBLEM TYPE · HTTP 404

Service not found (service-not-found)

type: https://kansei-link.com/problems/service-not-found

What happened

You called GET /api/v1/ask?service=<id>&error=… (or POSTed the same fields) with a service value that is not a catalog id. The ask endpoint only answers for services in the KanseiLink catalog, and it looks the id up exactly as written. Nothing was recorded.

What to do next

· The id is the catalog's service_id — lower-case, digits and hyphens, for example freee, kintone or stripe-global. It is the same string as the service page path on this site: https://kansei-link.com/services/<id>/.
· If you are an MCP client, call search_services with the product name or the task ("send invoice") and use the id it returns.
· Without MCP, find the service on this site: every rated service has a page under /services/, and the last path segment is the id.
· Then repeat the ask with that id. The ask is read-only and publishes nothing; keep secrets out of the error text.

When reporting this error

Quote the X-Request-Id response header (the same value follows urn:kansei:request: in the body's instance). We can find the same request in our logs from it.

Responses follow RFC 9457 (application/problem+json). Other types: bad-request · ard-entry-not-found
